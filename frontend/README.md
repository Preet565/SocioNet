# NPC Internet · The Butterfly Effect

Standalone React + TypeScript + Vite frontend for the simulation command center. It owns only the files in `frontend/` and expects a backend API at `VITE_API_URL`.

## Runtime and setup

- Node.js `22.22.0` (see `.nvmrc`)
- npm lockfile: `package-lock.json` is generated by `npm install`
- Copy `.env.example` to `.env` when the API is not running at the default URL.

```sh
cd frontend
npm install
npm run dev
```

Open <http://localhost:5173>. The default API URL is `http://localhost:8000`.

## API contract used by the frontend

The adapter in `src/api.ts` normalizes common snake_case and camelCase payloads. The expected endpoints are:

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/health` | API health and optional version/tick |
| GET | `/state?universe_id=prime\|echo` | Full universe snapshot: metrics, nodes, edges, citizens, sources, experiments, interventions, minds |
| GET | `/citizens?universe_id=...` | Citizen roster refresh |
| GET | `/citizens/:id?universe_id=...` | Selected citizen detail |
| GET | `/experiments?universe_id=...` | Experiment registry |
| POST | `/tick` | `{ universe_id, steps }` |
| POST | `/reset` | `{ universe_id }` |
| POST | `/experiments/run` | `{ universe_id, experiment_id }` |
| POST | `/experiment-runs` | Create a durable experiment run with tagged provenance |
| GET | `/experiment-runs?universe_id=...` | Durable run history and status |
| GET | `/experiment-runs/:run_id` | Retrieve a saved result and snapshot provenance |
| GET | `/experiment-runs/:run_id/export` | Download the saved run JSON |
| POST | `/interventions` | `{ universe_id, action, target, intensity, rationale }` |

The graph view is built from the returned `nodes` and `edges` arrays; it does not use a mock graph when the API is live. Butterfly Lab loads durable history on entry and renders source/control/treatment snapshot tags with an export link. The catalog status in the state projection comes from the durable run record.

## Offline recovery path

If the API cannot be reached during initialization or an action, the UI switches to a clearly labelled **Offline preview**. It uses deterministic local seed data from `src/data.ts` so the interface remains explorable. Preview mutations are labelled as preview-only and are never presented as live backend outcomes. A refresh action becomes available again once the API is reachable.

## Verification

```sh
npm run typecheck
npm run build
npm test
```

`npm test` is the single offline-safe test command and runs the TypeScript project check. `npm run build` performs the production Vite build.

## Production container

```sh
docker build -t npc-internet-frontend .
docker run --rm -p 8080:80 npc-internet-frontend
```

The static container serves the built frontend at <http://localhost:8080>. Configure `VITE_API_URL` at build time when deploying against a non-default API:

```sh
docker build --build-arg VITE_API_URL=https://api.example.test -t npc-internet-frontend .
```
